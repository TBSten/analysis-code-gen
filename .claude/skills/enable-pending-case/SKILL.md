# 保留テストを有効にする

R-01（`.claude/rules/pending-case.md`）: 許される変化は 保留 → 有効 だけ。期待値は変えない。

1. **ケース ID を決める**: 実装したチケットに書かれたケース ID（例: `GRD-01`）。`quality/test-cases.csv` で内容と担当マイルストーンを確かめる
2. **保留を外す**: テストから `@PendingCase`（ACG-37 で入る仕組み）を外す。**アサーション・入力・期待値には手を触れない**
3. **そのテストだけ回す**
   ```bash
   ./gradlew :<module>:test --tests '<テストクラスの FQCN>' --console=plain
   ```
4. **落ちたら直すのは実装側**。テストが仕様（docs・ADR）と食い違っていると判断したときだけテストを直してよく、その場合は ADR に理由を書いて PR に明記する
5. **3 回続けて回して安定を確かめる**（flaky は通っていない扱い）
6. **PR に書く**: テンプレートの「保留を外したケース」に ID を列挙する。進捗レポートはこの数で進む

## やってはいけないこと

- 期待値をいまの出力に合わせて書き換える（スナップショットの更新を含む。新しいスナップショットは仕様と突き合わせてから）
- 通らない部分だけ別テストに分けて、そちらを保留にする
- 一度外した保留を、別の PR で付け直す
