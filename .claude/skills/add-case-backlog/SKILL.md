# テストケースの候補を溜める

途中で見つけたケースは一覧（分母）に直接足さず、候補置き場に溜める（`pm/14-pm-plan.md`「途中で気づいたテストケースの溜め方」）。

1. **まず既存ケースの不具合でないか確かめる**: すでに通っているケースが壊れているだけなら、それは不具合。既存のケース ID に紐づけた回帰テストとして**すぐ足す**（候補にしない）。PBT の反例を固定シードにするのも同じ
2. **候補置き場に 1 行足す**: `quality/case-backlog.md`（リポジトリへ移るまでは共有フォルダ `quality/case-backlog.md`。編集の直前に読み直す）
   ```markdown
   | CB-<次の番号> | <内容> | E / P / D | YYYY-MM-DD / ACG-n | <気づいたきっかけ> | <入れたいマイルストーン> | 未 |
   ```
   種類: E = E2E、P = PBT の入力パターン、D = 差分テスト
3. **今のマイルストーンには入れない**: 取り込みはマイルストーン達成時と振り返りのときだけ（サポート Agent が振り分ける）
4. **大きいものは上げる**: 誤ったコードを黙って生成する・ビルドを壊す候補は、チケットを `人間:判断待ち` にして進捗レポートの判断待ちに載せる
