# 再開と引き継ぎ

Agent は費用・クールタイム・障害でいつ止まってもよい。止まった Agent の続きを別の Agent が拾えるよう、状態を 3 層に分けて残す（`pm/14-pm-plan.md`「中断と再開」）。

| 層 | 残すもの | 置き場所 |
|---|---|---|
| 決定 | 決め打ちした仕様と理由 | ADR（`pm/adr/`） |
| 作業状態 | 次の一手・詰まっている点 | Notion の作業チケット（`## 次の一手` 節と Next 列） |
| 成果 | コードとテスト結果 | git（小さく commit、早めに push）とテストケースの通過状況 |

## 再開の手順

1. テストケースの通過状況を見る（`quality/` の一覧、main の CI、進捗レポート）
2. 担当チケットの `## 次の一手` と Next 列を読む。スレッド 1 つ ↔ チケット 1 つ
3. チケットの背景情報からリンクされた ADR を読む
4. `git fetch` して自分の branch と main の差を確かめてから続ける

## 止まる前（引き継ぎ）

- 毎日 03:00〜09:00 JST はクールタイム（Agent を止める）。**02:45 までに**作業中のチケットの `## 次の一手` と Next 列を書き、作業中のコードを push する
- `## 次の一手` には「再開したら最初に打つコマンド / 開くファイル」まで書く。「続きをやる」のような曖昧な書き方は禁止
- push していない作業は失われる前提で動く。WIP でも branch に push してよい（main には入れない）

## 区切りの大きさ

- 1 つの作業は数時間で区切れる大きさにする。大きいときはチケットを分ける
- 区切りごとに commit → push → チケット更新 の 3 つをまとめて行う
