# ドキュメントの分量と構成

人間のレビューを軽くするため、情報量の多いドキュメントを書かない。お手本は katachi の Basic API ガイド。基準の正は `pm/14-pm-plan.md`「ドキュメントの構成と分量の基準」。CI のチェック script は ACG-29 で入る。

| チェック | 基準（日本語の文字数、コード・表・リストを除く本文） |
|---|---|
| ページ全体 | 1,400 字以下 |
| 1 段落 | 100 字以下 |
| H2 節 | 320 字以下 |
| コードブロック | 1 個 15 行以下 |
| 見出し | H2 は 8 個以下、深さは H3 まで |

- ガイドページの型: 各 H2 節で ①紹介 1〜2 文 → ②4〜13 行のコード例 → ③説明 1〜2 文 → ④詳細へのリンク。最後に Summary の表と Next steps
- 基準を超える説明は詳細ページへ、内部の話は Internal / Architecture へ分ける
- docs のコード例は後で E2E テストとして実行できる形で書く（仕様とテストを対応させる）
- 判断してほしい論点は各ページの冒頭にまとめる
- 当面すべて日本語。英語版は作らない
- `CLAUDE.md` や `.claude/` などの Agent 向けファイルは基準の対象外だが、短く保つ
