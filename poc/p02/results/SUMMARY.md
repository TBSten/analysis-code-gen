# PoC P-02 結果のまとめ（2026-11-26）

採用条件（pm/24、検証前に決定）: 維持方式の「差分反映 + 再解析」が再構築方式の「環境構築 + 再解析」の 50% 以下（2 ラウンド目、中央値、ウォームアップ後、200 ファイル、宣言レベル解析）。

## 正しさ: 成立

すべての構成・ラウンドで、維持方式（KEEP）と再構築方式（REBUILD）の解析結果テキストが一致した。最終ラウンドはエラー 0 件。
無効化を抜くと（NO_INVALIDATE）ラウンド 2 以降で結果が変わる（既存クラスの上位型が `User0Base` のまま未解決になる）ので、この比較は無効化の有無を見分けられる。

| 構成 | 宣言レベル | 全解析（本体・診断） |
|---|---|---|
| 200 ファイル・依存 47 JAR | 3 ラウンドとも一致 | 3 ラウンドとも一致（エラー 867 → 400 → 0） |
| 200 ファイル・stdlib + JDK のみ | 一致 | 一致 |
| 1000 ファイル・依存 47 JAR | 一致 | 未計測 |

## 時間: 未達（2 ラウンド目で 61〜70%）

| 構成 | 2 ラウンド目 KEEP / REBUILD | 3 ラウンド目 | ラウンド間の処理だけ（2 ラウンド目） |
|---|---|---|---|
| 200・依存 47 JAR・Application 使い回し（判定の主条件） | 73.7 / 120.1 ms = **61.4%** | 43.0% | 12.6 / 41.4 ms |
| 同上（再計測） | 68.5 / 105.0 ms = **65.2%** | 49.2% | 12.1 / 37.3 ms |
| 200・stdlib + JDK・Application 作り直し | 104.7 / 149.9 ms = **69.9%** | 47.6% | 14.5 / 45.2 ms |
| 1000・依存 47 JAR・Application 使い回し（参考） | 368.5 / 508.9 ms = **72.4%** | 56.6% | 61.4 / 210.2 ms |
| 200・stdlib + JDK・作り直し・全解析（参考） | 81.8% | 80.6% | — |

ラウンド間の処理そのものは維持方式が 3〜4 倍速い。しかし無効化の後の再解析は、作り直した環境での解析とほぼ同じ時間がかかる（ソースの FIR セッションが丸ごと作り直されるため）。短縮できるのは環境構築の分だけなので、比率は 50% を切らない。

ソースモジュールの out-of-block 変更イベントに狭めても（KEEP_OOB）、結果は正しいが時間は変わらない（66.9% / 49.9%）。モジュールが 1 つなので、無効化される範囲が同じだから。
